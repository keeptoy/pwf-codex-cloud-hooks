## 1. Fresh setup and owned-inventory probe

Run this as the Cloud initialization script in a fresh sandbox after filling the
two published hashes:

```bash
set -Eeuo pipefail

TAG="v0.3.0-alpha.2"
ZIP="pwf-codex-cloud-hooks-${TAG}.zip"
ZIP_SHA256="61f2001f3dd3934d79144d5f1be09385a55936aba9f7481ad5e2177a486059db"
BOOTSTRAP="/tmp/init-cloud-sandbox-v0.3.0-alpha.2.bash"
BOOTSTRAP_SHA256="9328748023b401df8d4cbf98c48b2885978ba074654c94a09a46cae264c2869d"
BASE_URL="https://github.com/keeptoy/pwf-codex-cloud-hooks/releases/download/${TAG}"

curl --fail --location --retry 3 --output "$BOOTSTRAP" \
  "$BASE_URL/init-cloud-sandbox-v0.3.0.bash"
printf '%s  %s\n' "$BOOTSTRAP_SHA256" "$BOOTSTRAP" | sha256sum --check -
bash "$BOOTSTRAP" all

PROBE_DIR="$(mktemp -d)"
trap 'rm -rf -- "$PROBE_DIR"' EXIT
curl --fail --location --retry 3 --output "$PROBE_DIR/$ZIP" "$BASE_URL/$ZIP"
printf '%s  %s\n' "$ZIP_SHA256" "$PROBE_DIR/$ZIP" | sha256sum --check -
unzip -q "$PROBE_DIR/$ZIP" -d "$PROBE_DIR/package"
INSTALLER="$PROBE_DIR/package/pwf-codex-cloud-hooks/install.js"

node "$INSTALLER" doctor --json \
  --codex-home /opt/codex \
  --skill-root /root/.agents/skills/planning-with-files \
  --managed-requirements /etc/codex/requirements.toml

python3 - <<'PY'
import hashlib

import os
from pathlib import Path

runtime = Path('/opt/codex/hooks/planning-with-files')

    'upstream/ledger-summary.sh',
    'upstream/resolve-plan-dir.sh',
    'upstream/session-catchup.py',

    str(path.relative_to(runtime))
    for path in runtime.rglob('*')
    if path.is_file() and path.name != 'installed-manifest.json'

assert manifest['schema_version'] == 3
assert {item['path'] for item in manifest['runtime_files']} == expected

    target = runtime / item['path']
    assert hashlib.sha256(target.read_bytes()).hexdigest() == item['sha256']
assert (runtime.stat().st_mode & 0o777) == 0o755
assert ((runtime / 'upstream').stat().st_mode & 0o777) == 0o755

skill_catchup = Path('/root/.agents/skills/planning-with-files/scripts/session-catchup.py')

assert skill_sha == '6476fd9024d0cbb9bfb850119fd0beff7fb7cfab9c6683ce10e4cc8d830ce6de'
```

## 2. Root/root and synthetic cross-user execution

Run after setup in the same sandbox. This creates only a temporary fixture and
executes the actually installed adapter/runtime:

```bash
set -Eeuo pipefail

ADAPTER="/opt/codex/hooks/planning-with-files/hook_adapter.py"
FIXTURE="$(mktemp -d)"
trap 'rm -rf -- "$FIXTURE"' EXIT
PROJECT="$FIXTURE/project"
PLAN="$PROJECT/.planning/owned-acceptance"
STORE="$FIXTURE/sessions"
TRANSCRIPT="$STORE/2026/08/02/rollout-owned-acceptance.jsonl"
SESSION_ID="pwf-alpha2-owned-acceptance"

mkdir -p "$PLAN" "$(dirname "$TRANSCRIPT")"
printf '%s\n' 'owned-acceptance' > "$PROJECT/.planning/.active_plan"
printf '%s\n' '# Task Plan: Alpha2 Owned Acceptance' > "$PLAN/task_plan.md"
printf '%s\n' '# Progress' '- fixture ready' > "$PLAN/progress.md"
printf '%s\n' '# Findings' > "$PLAN/findings.md"

python3 - "$TRANSCRIPT" "$PROJECT" "$PLAN/task_plan.md" "$SESSION_ID" <<'PY'
import json
import sys
from pathlib import Path

target, project, plan_file, session_id = sys.argv[1:]
records = [
    {'type': 'session_meta', 'payload': {
        'id': session_id, 'session_id': session_id,
        'cwd': project, 'source': 'vscode',
    }},
    {'type': 'event_msg', 'payload': {
        'type': 'patch_apply_end', 'success': True,
        'changes': {plan_file: None},
    }},
    {'type': 'response_item', 'payload': {
        'type': 'message', 'role': 'user',
        'content': [{'type': 'input_text', 'text': 'PWF_ALPHA2_OWNED_TAIL_SENTINEL'}],
    }},
]
Path(target).write_text('\n'.join(json.dumps(item) for item in records) + '\n')
PY

find "$FIXTURE" -type d -exec chmod 755 {} +
find "$FIXTURE" -type f -exec chmod 644 {} +
PAYLOAD="$(python3 - "$PROJECT" "$TRANSCRIPT" "$SESSION_ID" <<'PY'
import json, sys
print(json.dumps({
    'cwd': sys.argv[1], 'hook_event_name': 'SessionStart',
    'source': 'resume', 'transcript_path': sys.argv[2],
    'session_id': sys.argv[3],
}))
PY
)"

ROOT_OUTPUT="$(printf '%s' "$PAYLOAD" | \
  CODEX_HOME=/opt/codex CODEX_SESSIONS_DIR="$STORE" \
  /usr/bin/python3 "$ADAPTER" SessionStart)"
printf '%s\n' "$ROOT_OUTPUT" | grep -F 'SESSION CATCHUP DETECTED'
printf '%s\n' "$ROOT_OUTPUT" | grep -F 'PWF_ALPHA2_OWNED_TAIL_SENTINEL'

command -v runuser >/dev/null
SPLIT_OUTPUT="$(printf '%s' "$PAYLOAD" | runuser -u nobody -- \
  env HOME="$FIXTURE" CODEX_HOME=/opt/codex CODEX_SESSIONS_DIR="$STORE" \
  /usr/bin/python3 "$ADAPTER" SessionStart)"
printf '%s\n' "$SPLIT_OUTPUT" | grep -F 'SESSION CATCHUP DETECTED'
printf '%s\n' "$SPLIT_OUTPUT" | grep -F 'PWF_ALPHA2_OWNED_TAIL_SENTINEL'

PROMPT_OUTPUT="$(printf '%s' "{\"cwd\":\"$PROJECT\",\"hook_event_name\":\"UserPromptSubmit\",\"session_id\":\"$SESSION_ID\",\"turn_id\":\"turn-1\"}" | \
  CODEX_HOME=/opt/codex /usr/bin/python3 "$ADAPTER" UserPromptSubmit)"
printf '%s\n' "$PROMPT_OUTPUT" | grep -F 'Task Plan: Alpha2 Owned Acceptance'
if printf '%s\n' "$PROMPT_OUTPUT" | grep -Fq 'SESSION CATCHUP DETECTED'; then
  echo 'UserPromptSubmit unexpectedly launched catch-up' >&2
  exit 1
fi

printf '%s\n' ROOT_ROOT_OWNED_CATCHUP=PASS SYNTHETIC_CROSS_USER=PASS USERPROMPT_LOCAL_ONLY=PASS
```

This is the explicit permission contract: the installed runtime, project, and
session store must all be traversable/readable by the Hook identity. The test
does not claim that arbitrary private project/session directories work across
users.

## 3. Fresh-task lifecycle and resume black box

Start a completely new Codex Cloud task using the installed environment. Do not
manually read Hook files. Confirm the first reply actually observes both canaries
and planning context. Then create/update the scoped planning files through
`apply_patch`, send a long wrapped user message ending in a unique sentinel,
resume the same task, and use the existing no-tools session-catchup prompt.

Acceptance requires all of the following:

- `SessionStart source=startup` and `UserPromptSubmit` canaries are observed;
- resume reports `SESSION CATCHUP DETECTED` and `Runtime: codex`;
- the selected previous session and planning-update line are real;
- the unique tail sentinel survives bounded rendering;
- scoped Planning context is also present;
- `node install.js doctor ...` remains healthy after resume;
- the global Skill catch-up hash remains pristine.

Record the exact observed report and doctor JSON. Any missing item is a Phase 2
failure; roll back to alpha.1 and diagnose before Phase 3.
