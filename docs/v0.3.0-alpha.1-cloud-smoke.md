# v0.3.0-alpha.1 pre-release Cloud smoke

This is the Phase 1 handoff. It validates supply-chain, installation inventory,
doctor, and the unchanged v0.2.2-compatible Hook behavior. It does not activate
the staged owned runtime scripts.

## Publish these two separate assets

GitHub pre-release tag: `v0.3.0-alpha.1`

| Asset | Local source | SHA-256 |
|---|---|---|
| `pwf-codex-cloud-hooks-v0.3.0-alpha.1.zip` | `dist/pwf-codex-cloud-hooks-v0.3.0-alpha.1.zip` | `94fe21837d26bbe07d23cdf88b89133c12e6f431eafd8c412ece96204f6a5027` |
| `init-cloud-sandbox-v0.3.0.bash` | repository root | `17e2248d04027001a929dbc07fcf06c6f4a9cb727530fcdb99edbcc4e90fba32` |

Do not put the Bash inside the ZIP. Release sealing order is: freeze the version
and ZIP contents, build and hash the ZIP, write the version/package/ZIP SHA into
the external Bash, hash the sealed Bash, then publish and verify both assets.
The Bash SHA cannot be finalized before its ZIP inputs are known.

## Post-start inventory probe

After the first model response, run:

```bash
set -Eeuo pipefail

PROBE_DIR="$(mktemp -d)"
trap 'rm -rf -- "$PROBE_DIR"' EXIT
curl --fail --location --retry 5 --retry-all-errors \
  "https://github.com/keeptoy/pwf-codex-cloud-hooks/releases/download/v0.3.0-alpha.1/pwf-codex-cloud-hooks-v0.3.0-alpha.1.zip" \
  --output "$PROBE_DIR/candidate.zip"
printf '%s  %s\n' \
  "94fe21837d26bbe07d23cdf88b89133c12e6f431eafd8c412ece96204f6a5027" \
  "$PROBE_DIR/candidate.zip" | sha256sum --check --strict
unzip -q "$PROBE_DIR/candidate.zip" -d "$PROBE_DIR/extracted"

node "$PROBE_DIR/extracted/pwf-codex-cloud-hooks/install.js" doctor \
  --codex-home /opt/codex \
  --skill-root /root/.agents/skills/planning-with-files \
  --managed-requirements /etc/codex/requirements.toml --json

python3 - <<'PY'
import hashlib
import json
from pathlib import Path

runtime = Path('/opt/codex/hooks/planning-with-files')
requirements = Path('/etc/codex/requirements.toml').read_text()
manifest = json.loads((runtime / 'installed-manifest.json').read_text())
expected = {
    'THIRD_PARTY_NOTICES.md',
    'compatibility-overlays-v1.json',
    'hook_adapter.py',
    'installed-manifest.json',
    'upstream/inject-plan.sh',
    'upstream/ledger-summary.sh',
    'upstream/resolve-plan-dir.sh',
    'upstream/session-catchup.py',
}
actual = {
    path.relative_to(runtime).as_posix()
    for path in runtime.rglob('*')
    if path.is_file()
}

print(f'manifest_schema={manifest.get("schema_version")}')
print(f'runtime_files={len(manifest.get("runtime_files", []))}')
print(f'inventory_exact={actual == expected}')
print(f'unknown={sorted(actual - expected)}')
print(f'missing={sorted(expected - actual)}')
print('adapter_commands_only=' + str(
    requirements.count('hook_adapter.py') == 2 and '/upstream/' not in requirements
))
for entry in manifest.get('runtime_files', []):
    target = runtime / entry['path']
    digest = hashlib.sha256(target.read_bytes()).hexdigest()
    print(f'{entry["path"]}={digest == entry["sha256"]}')
PY
```

The bootstrap itself already runs installer dry-run, install, doctor, managed
policy checks, and both current adapter canaries. The additional probe must show
manifest schema 3, seven payload files, exact eight-file installed inventory,
and every per-file hash as `True`.

### Observed Cloud result (2026-08-02)

The published candidate passed this section in a fresh Cloud task:

- the 59,097-byte ZIP downloaded and matched the pinned SHA-256;
- doctor reported `healthy=true`, `repairable=false`, managed mode, and exactly
  `SessionStart` plus `UserPromptSubmit`;

- installed inventory was exact, with no unknown or missing files;

- `adapter_commands_only=True`, so no staged `upstream/` script was registered.

This proved the supply-chain/install/inventory portion. The compatibility smoke
below subsequently passed as recorded in the final result section.

## Compatibility smoke

Run the simplified v0.2.2 checks from `黑盒验证.md`:

- `SessionStart source=startup` canary;
- `UserPromptSubmit` canary and scoped planning context;
- resume catch-up with `Runtime: codex`;
- bounded long wrapper with the tail sentinel still visible;
- `doctor` remains `healthy=true` after resume.

Stop and retain the task if the inventory is not exact, doctor is unhealthy,
the Hook command points directly at an `upstream/` script, the global Skill is
not at the approved managed hash, or any newly staged runtime file executes.
