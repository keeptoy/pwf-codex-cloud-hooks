- ZIP 中的 README 纳入 beta.1 发布后的文档治理与打包说明；

## 3. 发布前：Fresh Cloud exact-byte seal

需要复验确定性字节时，把包含本文件与 beta.2 修改的 checkpoint 推送到远端后，在全新 Cloud
沙箱的仓库根目录执行以下完整脚本。不得安装到 live `/opt/codex`，不得修改仓库：

```bash
set -Eeuo pipefail

EXPECTED_ZIP_SHA256="812cc9cdcafa93b5fcc47cc763fd743f11be77958b75eea1fa4cf0508dd391ab"
EXPECTED_BOOTSTRAP_SHA256="d572b77d920b34c34c7912ba364376ae3668216f00ce350251bd7c8b336abcd6"
PROBE_DIR="$(mktemp -d)"

ZIP="$PROBE_DIR/pwf-codex-cloud-hooks-v0.3.0-beta.2.zip"

python3 tools/import_upstream_runtime.py check

python3 tools/build_release.py check --archive "$ZIP"

test "$(python3 -c 'import json; print(json.load(open("package.json", encoding="utf-8"))["version"])')" = "0.3.0-beta.2"
test "$(find "$PROBE_DIR" -maxdepth 1 -name '*.zip' -type f | wc -l)" -eq 1
test "$(unzip -Z1 "$ZIP" | wc -l)" -eq 22

grep -Fq "HOOKS_SHA256=\"\${HOOKS_SHA256:-$EXPECTED_ZIP_SHA256}\"" init-cloud-sandbox-v0.3.0.bash
```

Cloud/Linux 必须报告 69/69/0/0；Windows 的 18 个 POSIX/Linux-only SKIP 不能替代此门槛。

## 4. A：发布后下载复核与安装

发布 tag `v0.3.0-beta.2` 后，可在 Fresh Cloud 下载发布资产进行复验；必须下载 Release 资产，
而不是使用 checkout 中的本地文件：

```bash
set -Eeuo pipefail

TAG="v0.3.0-beta.2"
ZIP="pwf-codex-cloud-hooks-${TAG}.zip"
ZIP_SHA256="812cc9cdcafa93b5fcc47cc763fd743f11be77958b75eea1fa4cf0508dd391ab"
BOOTSTRAP="/tmp/init-cloud-sandbox-v0.3.0-beta.2.bash"
BOOTSTRAP_SHA256="d572b77d920b34c34c7912ba364376ae3668216f00ce350251bd7c8b336abcd6"
BASE_URL="https://github.com/keeptoy/pwf-codex-cloud-hooks/releases/download/${TAG}"
PROBE_DIR="$(mktemp -d)"
trap 'rm -rf -- "$PROBE_DIR" "$BOOTSTRAP"' EXIT

curl --fail --location --retry 3 --output "$PROBE_DIR/$ZIP" "$BASE_URL/$ZIP"
curl --fail --location --retry 3 --output "$BOOTSTRAP" "$BASE_URL/init-cloud-sandbox-v0.3.0.bash"
printf '%s  %s\n' "$ZIP_SHA256" "$PROBE_DIR/$ZIP" | sha256sum --check -
printf '%s  %s\n' "$BOOTSTRAP_SHA256" "$BOOTSTRAP" | sha256sum --check -

unzip -q "$PROBE_DIR/$ZIP" -d "$PROBE_DIR/package"
PACKAGE_ROOT="$PROBE_DIR/package/pwf-codex-cloud-hooks"
test "$(find "$PACKAGE_ROOT" -type f | wc -l)" -eq 22
test ! -e "$PACKAGE_ROOT/init-cloud-sandbox-v0.3.0.bash"
node -e 'const p=require(process.argv[1]); if(p.version!=="0.3.0-beta.2") process.exit(1)' \
  "$PACKAGE_ROOT/package.json"
python3 "$PACKAGE_ROOT/tools/build_release.py" check \
  --contract "$PACKAGE_ROOT/contracts/release-artifact-v1.json" \
  --archive "$PROBE_DIR/$ZIP"

bash "$BOOTSTRAP" all
node "$PACKAGE_ROOT/install.js" doctor --json \
  --codex-home /opt/codex \
  --skill-root /root/.agents/skills/planning-with-files \
  --managed-requirements /etc/codex/requirements.toml

echo "BETA2_ASSET_DOWNLOAD_AND_SETUP=PASS"
```

安装成功后结束 setup task，再启动一个完全新的 Codex Cloud task。不要复用已经运行的 session。

## 5. B～F：live lifecycle 与 Resume

beta.2 没有改变 lifecycle 语义，因此 B～F 的提示词、操作顺序和严格判定沿用
[`v0.3.0-beta.1-cloud-hard-acceptance.md`](v0.3.0-beta.1-cloud-hard-acceptance.md) 第 4～8 节，
但必须在一套新的 beta.2 Fresh/Resume 会话中执行，并做以下精确替换：

| beta.1 字段 | beta.2 字段 |
|---|---|
| `v0.3.0-beta.1` / `0.3.0-beta.1` | `v0.3.0-beta.2` / `0.3.0-beta.2` |
| `PWF_BETA1_CANONICAL_PLAN_B71C` | `PWF_BETA2_CANONICAL_PLAN_C82D` |
| `PWF_BETA1_BASELINE_CREATED` | `PWF_BETA2_BASELINE_CREATED` |
| `PWF_BETA1_UNSYNCED_ACKNOWLEDGED` | `PWF_BETA2_UNSYNCED_ACKNOWLEDGED` |
| `PWF_BETA1_REAL_RESUME_TAIL_B71C` | `PWF_BETA2_REAL_RESUME_TAIL_C82D` |

不得替换协议 canary `PWF_GLOBAL_HOOK_CANARY_V1`。B～F 仍须证明：

1. Fresh `SessionStart source=startup` 与 `UserPromptSubmit` 自动 canary；
2. canonical plan、`===BEGIN PLAN DATA===` 和 recent progress 自动注入；
3. 真实 planning update 后的长 wrapper 被有界截断且尾部 beta.2 sentinel 保留；
4. Resume 自动报告 `SESSION CATCHUP DETECTED`、`Runtime: codex`、previous session、update 和
   unsynced count，catch-up 位于 planning context 之前；
5. post-resume doctor 为 `healthy=true`、`repairable=false`、errors/blockers 空；
6. 安装目录是 11 个 manifest payload 加单独 manifest，二者精确一致；
7. `/tmp/pwf-codex-cloud-hooks-<uid>/pwf-snapshot-*` residue 为 0。

任一项失败都不得修改已发布 beta.2 资产。先回退到 beta.1，诊断后发布新的版本身份。
